### 1. How Current Resolves Account, Identity, and User

The `Current` class extends `ActiveSupport::CurrentAttributes` and manages request-scoped state:

**File: `~/Projects/37signals/fizzy/app/models/current.rb`**

```ruby
class Current < ActiveSupport::CurrentAttributes
  attribute :session, :user, :identity, :account
  attribute :http_method, :request_id, :user_agent, :ip_address, :referrer

  def session=(value)
    super(value)
    if value.present?
      self.identity = session.identity
    end
  end

  def identity=(identity)
    super(identity)
    if identity.present?
      self.user = identity.users.find_by(account: account)
    end
  end

  def with_account(value, &)
    with(account: value, &)
  end

  def without_account(&)
    with(account: nil, &)
  end
end
```

**Resolution flow:**
- When `Current.session` is set, it automatically extracts and sets `Current.identity` from the session
- When `Current.identity` is set, it automatically resolves `Current.user` by finding the user record that belongs to the current account via `identity.users.find_by(account: account)`
- This cascading setter pattern ensures the three are always in sync
- The Account is typically set by middleware before session/identity resolution

## Authentication Flow Summary

```
1. User enters email on /sessions/new
   ↓
2. POST /sessions → checks Identity.find_by(email_address)
   ↓
3. identity.send_magic_link → creates MagicLink, sends email
   ↓
4. System sets pending_authentication_token cookie (verified, expires_at)
   ↓
5. Redirect to /sessions/magic_link (show form for code entry)
   ↓
6. User enters 6-char code → POST /sessions/magic_links/create
   ↓
7. Validate MagicLink.consume(code) & verify email match
   ↓
8. start_new_session_for(identity) → creates Session, sets signed cookie
   ↓
9. Current.session = session → triggers identity= → user resolution
   ↓
10. Redirect to after_authentication_url or signup_completion_path
```

## Key Design Patterns

1. **Global Identity + Account-Scoped User** - Enables multi-account membership while keeping authentication global
2. **Cascading CurrentAttributes** - Session → Identity → User are automatically resolved in sequence
3. **Signed IDs for tokens** - Rails' built-in message verifier for magic link codes and session tokens
4. **HTTPOnly cookies with SameSite** - All authentication tokens are secure by default
5. **Account context via URL middleware** - Path-based tenancy is transparent to controllers/models
6. **Idempotent join mechanism** - Same Identity can join same Account multiple times safely (reactivation)

### 3. AccountSlug Middleware Architecture

**Location**: `config/initializers/tenanting/account_slug.rb`

The middleware is **always active** but has distinct behavior:

**Pattern Matching:**
```ruby
PATTERN = /(\d{7,})/          # Matches 7+ digit account IDs
FORMAT = "%07d"               # Encodes account IDs as 7+ digit strings
PATH_INFO_MATCH = /\A(\/#{AccountSlug::PATTERN})/  # Matches /1234567... at path start
```

**Core Logic:**
1. Extracts account ID prefix from URL path (e.g., `/1234567/boards/123`)
2. Moves the prefix from `PATH_INFO` to `SCRIPT_NAME` (tricks Rails into thinking it's "mounted" at that path)
3. Sets `env["fizzy.external_account_id"]` for lookups
4. Wraps the request in `Current.with_account(account)` or `Current.without_account` depending on whether an account was extracted

**Key Code Path:**
```ruby
def call(env)
  request = ActionDispatch::Request.new(env)

  # Handles edge case: rebuilding ActionCable after connection upgrade
  if request.script_name && request.script_name =~ PATH_INFO_MATCH
    env["fizzy.external_account_id"] = AccountSlug.decode($2)
  # Normal case: extract from PATH_INFO
  elsif request.path_info =~ PATH_INFO_MATCH
    request.engine_script_name = request.script_name = $1
    request.path_info = $'.empty? ? "/" : $'
    env["fizzy.external_account_id"] = AccountSlug.decode($2)
  end

  if env["fizzy.external_account_id"]
    account = Account.find_by(external_account_id: env["fizzy.external_account_id"])
    Current.with_account(account) do
      @app.call env
    end
  else
    Current.without_account do
      @app.call env
    end
  end
end
```

### 1. The Full Signup Flow (New Account Creation)

**Entry Point**: `GET /signup/new` → `SignupsController#new`

- If valid, calls `Signup#create_identity`:
  - Calls `Identity.find_or_create_by!(email_address: email_address)`
  - Calls `identity.send_magic_link(for: :sign_up)`
    - `Identity#send_magic_link` creates a `MagicLink` record and queues `MagicLinkMailer.sign_in_instructions` job
  - Returns the magic link object
- Controller redirects to magic link verification page via `redirect_to_session_magic_link`
  - Sets a signed cookie `pending_authentication_token` that contains the email (verified)
  - In development, stores the code in flash and headers for easy access
  - Redirects to `session_magic_link_url` for magic link validation

**Step 3: Magic Link Validation** (happens when user clicks link in email)
- User clicks magic link in email
- Magic link redirected to `/session/magic_links` with token
- Magic link is verified against database
- If valid and identity newly created, redirects to `new_signup_completion_path` (via `redirect_authenticated_user` before_action)

**Step 4: Signup Completion**
- User lands on `/signups/completions/new` (presented by `app/views/signups/completions/new.html.erb`)
- User already authenticated, so `Current.identity` is available
- Form requests: `full_name` (required, max 240 chars)
- On POST to `Signups::CompletionsController#create`:
  1. Calls `@signup.complete` which:
     - Validates presence of `full_name` and `identity` (via `valid?(:completion)`)
     - Calls `create_tenant` (can be overridden; default returns `nil`)
     - Calls `Account.create_with_owner`:
       - Creates new Account with `external_account_id` and generated `name`
       - Creates system User and owner User with `verified_at: Time.current`
     - Calls `setup_customer_template` on the account
  2. Sets flash `:welcome_letter` flag
  3. Redirects to landing page with account slug in script name: `landing_url(script_name: @signup.account.slug)`

**Step 5: Landing**
- `LandingsController#show` determines destination:
  - If user has exactly 1 board → redirect to that board
  - Otherwise → redirect to root (events index)

### 2. The Join-Code Flow (Joining Existing Account)

**Entry Point**: `GET /join/:code` → `JoinCodesController#new`

**Step 1: Join Code Display**
- Route handler `get "join/:code", to: "join_codes#new", as: :join`
- View `app/views/join_codes/new.html.erb` shows join form requesting email address
- Account name displayed: "Join #{@join_code.account.name} in Fizzy"

**Step 2: Join Code Redemption**
- Form POSTs to `post "join/:code", to: "join_codes#create"`
- `JoinCodesController#create`:
  1. `set_identity` action finds or initializes Identity by email:
     - `Identity.find_or_initialize_by(email_address: params[:email_address])`
     - If new record, validates and saves it
  2. `set_join_code` finds the join code:
     - `Account::JoinCode.find_by(code: params[:code], account: Current.account)`
  3. `ensure_join_code_is_valid` checks:
     - Code exists (404 if not)
     - Code is active: `usage_count < usage_limit` (status 410 gone if not)

**Step 3: Join Code Redemption Details**
- Calls `@join_code.redeem_if { |account| @identity.join(account) }`
- `Account::JoinCode#redeem_if` uses lock and calls block if code is active:
  - Block executes `@identity.join(account)` via `Identity::Joinable` mixin:
    - Calls `account.users.find_or_create_by!(identity: self)`:
      - If new user created: returns `true`, joins with email as default name
      - If existing deactivated user: reactivates (sets `active: true`) and returns `false`
    - Reactivated users manually granted board access via `grant_access_to_boards`
  - Increments `usage_count` if block returns `true`

**Step 4: Post-Join Routing**
After join code redemption, routes depend on context:
- If `@identity == Current.identity` (same person) AND user is setup (name != email):
  - Redirect to `landing_url(script_name: account.slug)` (direct to boards)
- If `@identity == Current.identity` AND user NOT setup:
  - Redirect to `new_users_verification_url(script_name: account.slug)`
- If `@identity != Current.identity` (different person):
  - Terminate current session
  - Send magic link for the join identity
  - Redirect to magic link page with `return_to: new_users_verification_url`
