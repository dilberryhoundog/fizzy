[SUMMARY]
>>>
Diagnosed and fixed two bugs preventing images from displaying in a self-hosted Fizzy deployment using Cloudflare R2 storage. The first fix added `credentials: "same-origin"` to the turbo-offline service worker's Active Storage fetch options, preventing CORS failures when the service worker followed cross-origin redirects to R2. The second fix added `script_name: Current.account&.slug` to `to_rich_text_attributes` in the Active Storage initializer, ensuring ActionText attachment URLs include the account prefix required by the multi-tenant routing middleware — without it, Lexxy editor image URLs returned 404. Both are upstream Fizzy bugs affecting S3-compatible storage deployments. Also resolved a Kamal deploy dependency issue (missing activesupport gem).

## Investigation Summary

Based on my thorough investigation of the codebase, here's why the ActionText attachment URL generation works differently in 37signals' multi-tenant Fizzy SaaS mode vs the single-tenant OSS mode:

### How Multi-Tenancy Works

**1. The Middleware Layer: `AccountSlug::Extractor`** (`~/Projects/bizzy/config/initializers/tenanting/account_slug.rb`)

The key to multi-tenancy is the `AccountSlug::Extractor` middleware that intercepts every request:

- **SaaS mode**: Requests come in with the account prefix in the URL (e.g., `/1/cards/123` or `/7/rails/active_storage/blobs/redirect/...`)
- **OSS mode**: Requests have no account prefix (e.g., `/cards/123` or `/rails/active_storage/blobs/redirect/...`)

The middleware:
1. Matches incoming paths against `PATH_INFO_MATCH = /\A(\/#{AccountSlug::PATTERN})/` (pattern matches numeric account IDs)
2. If a match is found, it **moves the account prefix from PATH_INFO to SCRIPT_NAME** (lines 20-22):
   ```ruby
   request.engine_script_name = request.script_name = $1
   request.path_info = $'.empty? ? "/" : $'
   ```
3. Stores the account ID in `env["fizzy.external_account_id"]` and sets `Current.account` via the `Current.with_account` context (lines 28-36)
4. If NO match is found (OSS mode), it calls `Current.without_account`, leaving `Current.account = nil`

**2. The Problem: Unscoped Blob URLs**

In `config/initializers/active_storage.rb` (line 17), the `to_rich_text_attributes` method was originally generating URLs without the account prefix:

```ruby
super.merge url: Rails.application.routes.url_helpers.polymorphic_url(self, only_path: true)
# Generated: /rails/active_storage/blobs/redirect/...
```

**Why this causes 404s in multi-tenant mode**: When Lexxy (the rich text editor) makes a client-side request to fetch these URLs to display images, the requests don't include the account prefix. The `AccountSlug::Extractor` middleware can't match them against the regex pattern, so it treats them as unauthenticated OSS-mode requests (`Current.without_account`). This causes the ActiveStorage controllers to fail authorization checks or require authentication setup that isn't configured for that context.

### The Fix

Your fix adds `script_name: Current.account&.slug` to the `polymorphic_url` call (line 17):

```ruby
super.merge url: Rails.application.routes.url_helpers.polymorphic_url(self, only_path: true, script_name: Current.account&.slug)
```

**How it works**:
- In **SaaS mode**: `Current.account&.slug` returns `/1` (or `/7`, etc.), so URLs become `/1/rails/active_storage/blobs/redirect/...`
- In **OSS mode**: `Current.account&.slug` returns `nil` (because `Current.account` is nil), so URLs become `/rails/active_storage/blobs/redirect/...` (no prefix)

Both cases now generate correct, scoped URLs that the middleware can properly route.

### Related Architecture Notes

1. **Fizzy.saas? toggle** (`~/Projects/bizzy/lib/fizzy.rb` lines 3-6): Determines whether to load `Gemfile.saas` and configures MySQL vs SQLite adapters. Does NOT control middleware behavior—the middleware is always active.

2. **SaaS Engine mounting** (`~/Projects/bizzy/saas/lib/fizzy/saas/engine.rb` line 34): The SaaS engine is mounted at the root, but routes are composed with the OSS app routes. Multi-tenancy is handled purely through the middleware and `Current.account` context.

3. **Active Storage Controller Extensions** (lines 36-46 of `active_storage.rb`): The `before_action` hook ensures `ActiveStorage::Current.url_options` includes `script_name: request.script_name`, which means disk service URLs for direct uploads already work correctly because they inherit the script_name from the request.

4. **Webhook URLs handling** (line 177 of `~/Projects/bizzy/app/models/webhook/delivery.rb`): Similar pattern—explicitly passes `script_name: account.slug` when generating webhook payload URLs.

### Why This Issue Exists

The original commit (Rosa Gutierrez, Jan 7 2026, `235890e66`) switched attachment URLs from absolute to relative URLs for portability across environments. However, relative URLs in a multi-tenant system must be smart about the account context. This wasn't captured in the initial implementation because it was designed for environments where all requests naturally include the account prefix. Your fix bridges this gap for clients (like Lexxy) that make standalone requests to fetch attachment URLs.
